# Zephyr 项目规范

## 1. 项目边界

Zephyr 是从零实现的 Minecraft 光影包。参考光影只用于学习渲染思想、比较视觉结果和制定性能目标；其源码、资源、许可证条款和品牌不进入 Zephyr 的实现边界。

仓库只发布：

- Iris shader 源代码；
- 使用说明、技术分析、设计和贡献文档；
- Apache-2.0 与 Zephyr 自有归属声明。

仓库不发布：

- 截图、录屏、游戏日志和启动报告；
- 本地选项、配置备份和机器相关路径；
- 预处理 shader、中间文件、缓存和 Python 环境；
- 从参考光影复制的源码、纹理、二进制数据或许可证文件。

## 2. 目录约定

```text
shaders/
├─ program/       # Iris 入口 pass
├─ include/       # 可复用 GLSL 模块
├─ texture/       # Zephyr 自有、可分发的纹理资源
├─ lang/          # 设置界面文本
└─ shaders.properties

docs/             # 稳定文档和设计记录
```

目录不存在时不为了占位提交空目录；第一个真实 shader 文件进入时再建立对应目录。

## 3. 命名和接口

- 自有宏、uniform、函数和文件名使用 `ZEPHYR_` 前缀或 `zephyr_` 前缀。
- 每个 pass 明确读写的 `colortex`、深度纹理、历史纹理和 mip 约定。
- 跨 pass 的数据格式必须在 `docs/` 记录：通道含义、精度、坐标空间和有效范围。
- 新模块先提供最低质量档位可运行的路径，再增加高质量路径。

## 4. 质量档位

设计至少包含 Low、Medium、High 三档：

| 档位 | 目标 |
| --- | --- |
| Low | 不依赖高成本时域或 compute 特性，优先保证兼容性和稳定帧率 |
| Medium | 开启主要阴影、天空和水体效果，允许半分辨率或简化时域 |
| High | 开启高质量光照、体积效果和后处理，明确记录显存与帧时间成本 |

Ultra 只有在 High 的质量和性能指标稳定后才增加。

## 5. 验证门槛

- 每次 shader 改动必须通过离线 GLSL 语法检查。
- 入口加载必须在目标 Iris 版本无编译错误。
- 视觉回归至少覆盖晴天、黄昏、雨天、夜间和室内五类场景。
- 时域效果必须检查拖影、闪烁、历史污染和快速转镜头的稳定性。
- 性能报告只保存在本地或外部发布材料，不进入源码仓库。

## 6. 变更策略

渲染系统按可独立验证的子系统推进：基础管线 → 阴影与材质 → 天空和大气 → 水体 → 时域与反射 → 体积效果 → 电影化后处理。每个子系统都要有独立开关、降级路径和文档说明。
